# Data planes: table map

Working map for the clean-cut split (epic 00290527). It assigns every
table declared under `packages/db/src/schema/` to a target plane:

- **core** — the shared core Postgres store: platform identity, org
  registries, billing, catalogs, governance, and the summary rows that
  cross-workspace readers consume.
- **workspace** — the per-workspace (tenant) SQLite store
  (`drizzle-orm/durable-sqlite`, `queries/durable-sqlite/tenant-store.ts`).
- **logs** — the append-only log classes the `LOGS_DB` retention path owns
  (`schema/logs-db.ts`, `docs/engineering/d1-log-storage.md`).
- **remove** — no live owner. None is proven dead yet; candidates are
  listed under Open items.

Scope key is the column set a table shards on today: `workspace` =
`workspace_id`, `project` = `project_id`, `tedi` = `tedi_id`,
`organization` = `organization_id`/`org_id`, `none` = no tenant column.
`+… via FK` marks scope inherited through declared references.
Query modules are the files under `packages/db/src/queries/` that read (R)
or write (W) the table; app-level direct-D1 owners are called out in notes.

Split marks tables that must shard below workspace: per test 2's finding
(Work 6c4c91b1), 65.7% of busy-day writes land in one project, so
project-keyed tables split by project, and tedi-keyed tenant tables split
by tedi inside the workspace store.

`⚑ no workspace key` flags workspace-plane tables that cannot shard on
`workspace_id` directly; each needs either a workspace key, a declared
project/tedi store key, or a reason to stay core.

Row counts: `—` pending an authorized live read. Produce them with
`bun scripts/db/d1-size-report.ts` (without `--sizes-only`) from an ops host
holding the installation's D1 ids; this lane has no Cloudflare credentials.

Totals: 189 core · 132 workspace · 5 logs · 326 tables.
